# OmniVoice native clients

Native shells around the OmniVoice web app for the three desktop/mobile platforms the web app does not cover.

| Platform | What | Status |
| --- | --- | --- |
| macOS | SwiftUI + WKWebView shell, SPM build, bundled via `scripts/bundle.sh` | built and verified on this machine |
| iOS | Same SwiftUI sources, Xcode project generated by xcodegen (`project.yml`) | project generates; needs Xcode to build (this machine has only Command Line Tools) |
| Windows | Tauri v2 shell (`windows/`), WebView2, MSI/NSIS bundles | source complete; needs a Windows machine to build |

## Run

The shell loads `http://localhost:5173` by default.

```bash
# 1. start the web app
cd .. && npm run dev

# 2. macOS app
cd native
./scripts/bundle.sh
open "dist/OmniVoice.app"
```

Override the server from the app's offline screen, or persist a different one
(macOS/iOS store it in UserDefaults under `serverURL`; Windows takes
`--url=http://...` or the `OMNIVOICESTUDIO_URL` environment variable).

## iOS build (machine with Xcode)

```bash
cd native
xcodegen generate
open OmniVoice.xcodeproj   # pick the "OmniVoice iOS" scheme, run
```

## Windows build (machine with Rust + Node)

```bash
cd native/windows
npm install -g @tauri-apps/cli   # once
cargo tauri build                # emits MSI + NSIS installers
```

Or without the CLI: `cargo build --release` inside `src-tauri` for a plain exe.
Point it at a running OmniVoice server with `--url=`.
